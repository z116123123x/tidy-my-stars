# Default React System

Use this bundled implementation when the user did not request another
compatible report system. It is a verified default, not the definition of
`explain-my-stars`.

## Private run directory

Keep `stars-analysis.json`, its complete semantic run directory, `stars-site/`,
`site-verification.json`, and browser evidence together in a private per-run
directory outside tracked, public, or synced locations whenever possible. The
semantic run contains `semantic-plan.json`, `collection-receipt.json`,
`execution-receipts.json`, `semantic-validation.json`, and frozen sources. On
POSIX, use mode `0700` for the run and all generated directories and `0600` for
generated files; on other platforms, apply equivalent current-user-only access
controls.

When the run is inside a Git worktree, use `git check-ignore --no-index` and
`git status --short --untracked-files=all` to confirm every intended sensitive
artifact is ignored and remains untracked. Relocate the run before building if
that cannot be guaranteed. A repository's own `.gitignore` does not protect an
installed skill running in another worktree.

## Build

The implementation requires Node.js and npm versions allowed by `site/package.json`.
Install the exact dependencies when absent:

```bash
cd <skill-directory>/site
npm ci
```

Build from the bundled React and Vite source. Do not hand-author, concatenate,
or template the report as HTML; `index.html` is only the mount shell.

```bash
node <skill-directory>/scripts/build-site.mjs \
  --input stars-analysis.json \
  --semantic-run <semantic-run-directory> \
  [--application-receipt <application-receipt.json>] --output stars-site
```

The builder independently revalidates the semantic plan, external receipts,
deterministic receipt, and exact candidate before it verifies installed
production package identities and versions against `package-lock.json`. It
preserves the already-validated analysis bytes in memory through the build,
bundles local hashed assets, and writes one schema-checked
`data/report-provenance.json` containing the candidate binding, all semantic
offline limitations, and any external application-receipt claim and
limitations. The React runtime requires that file as well as
`stars-analysis.json`; it does not compile an applied claim into the bundle.
Before parsing or exposing the analysis, the runtime hashes its exact fetched
bytes with Web Crypto SHA-256 and requires equality with the provenance binding.
The builder records both byte and semantic hashes and atomically replaces only
an output previously generated by this implementation.

When `--application-receipt` is supplied, its directory must contain the full
applied handoff: `stars-lists-diff.json`, finalized
`stars-rebuild-recovery.json`, `stars-current-pre-write-state.json`,
`application-preflight-validation.json`, `stars-final-state.json`,
`application-receipt.json`, and `application-validation.json`. The builder
deterministically revalidates all seven before it may present the external
receipt-backed applied claim.

## Deterministic verification

```bash
node <skill-directory>/scripts/verify-site.mjs \
  --input stars-analysis.json --semantic-run <semantic-run-directory> \
  [--application-receipt <application-receipt.json>] \
  --site stars-site \
  --output site-verification.json
```

The verifier revalidates the same complete semantic handoff, checks exact data
identity, rebuilds from that one in-memory snapshot, and checks Vite manifest
closure, route inventory, Content Security Policy, local assets, and the
complete output hash. Its receipt identifies the semantic candidate and
plan, collection, execution-receipts, and validation receipt hashes plus the
implementation as `bundled-react-v1` under receipt schema `3.0`. A validated
applied-state run deterministically revalidates the complete seven-file applied
handoff; the application receipt and validation hashes bind its exact diff,
finalized recovery journal, pre-write state, preflight validation, and final
state. Generated provenance preserves the exact deduplicated application
limitation array, including every preflight limitation and the post-write
final-state and mutation-response limitation. It also binds the generated
provenance while preserving the planned analysis bytes. A successful
deterministic run without rendered evidence is `passed-with-limitations`.

## Inspect the real experience

Serve `stars-site/` over loopback-only HTTP on `127.0.0.1` or `::1`; the React
hash router is not a `file://` artifact. Never omit the explicit loopback bind.
Use an isolated browser against the exact final bytes.

1. Test overview, site map, global search, List directory and detail,
   repository directory and detail, Likely Unstar queue and one-item review,
   Methods, and Print & export.
2. Test direct hash URLs, reload, Back/Forward, query restoration,
   `Cmd/Ctrl+K`, Arrow/Enter search selection, skip control, mobile menu, and
   report-local review decisions. Confirm a new frozen run does not inherit
   another run's decisions.
3. Inspect desktop `1440x900` and mobile `390x844`, long identities, empty
   states, console errors, runtime requests, focus order, accessible names,
   contrast, forced colors, reduced motion, and the complete print projection.
4. Record browser, visual, and accessibility evidence bound to both the exact
   input SHA-256 and `stars-site/` SHA-256. Never claim an unobserved pass.
5. Rerun `verify-site.mjs` with `--browser-evidence <file>`. Repair, rebuild,
   and repeat until the final `site-verification.json` passes or reports an
   honest unavailable capability.

The bundled site includes a provider-neutral automated Chromium runner for CI
and static publication gates:

```bash
cd <skill-directory>/site
npx playwright install chromium
npm run browser-qa -- \
  --input <absolute-stars-analysis.json> \
  --site <absolute-stars-site-directory> \
  --output <absolute-browser-evidence.json> \
  --artifacts <new-private-browser-qa-directory>
```

It checks the required desktop/mobile routes, search, deep links, history,
review decisions, keyboard navigation, 44px mobile targets, print,
forced-colors, reduced motion, runtime requests, console errors, screenshots,
and automated WCAG A/AA rules. Its hash-bound evidence is still subject to the
limitations it records; public deployment must require the final verifier
status to be exactly `passed`, never `passed-with-limitations`.

## React-specific safety

- Render source strings as React text. Never use `dangerouslySetInnerHTML`,
  `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `eval`, dynamic scripts, or
  inline event handlers with analysis data.
- Use hash routes so ordinary static HTTP servers support reload and deep links.
- Do not load runtime CDN, font, image, frame, script, analytics, or API
  dependencies. User-activated validated GitHub links and local Blob downloads
  are allowed.
- Refuse an all-interface bind, public tunnel, sync, publish, or deploy unless
  the user separately confirms publication after reviewing the exact generated
  analysis. A build, preview, or report-system choice is not authorization to
  make the artifact accessible to others.

## Deliverables

- `stars-site/`: the complete locally bundled report.
- `site-verification.json`: the final receipt for these exact site bytes.
- The original semantic run remains a required private provenance artifact; do
  not copy it into the rendered site.
